# STEP 2, 3 & 7 — Production Database Design Specification (`DATABASE_DESIGN.md`)

## 1. Architectural Overview & Design Principles

The database is designed for **PostgreSQL 15+ (hosted on Supabase)** and accessed via **Prisma ORM** within a **Next.js API** backend, while remaining 100% decoupled from any specific frontend implementation.

### Core Modeling Rules Enforced (STEP 3)
1. **UUID Primary Keys**: Every table uses `UUID` primary keys (`DEFAULT gen_random_uuid()` in PostgreSQL; deterministic `UUIDv5` generated by the Python importer for all book-migrated entities to guarantee idempotent re-imports).
2. **Strict Referential Integrity**: Foreign keys with explicit `ON DELETE` behaviors (`RESTRICT` / `CASCADE` / `SET NULL`) enforce structural invariants across chapters, topics, lessons, exercises, questions, and answers.
3. **High-Performance Indexing**: B-Tree indexes on all foreign keys, `code` slugs, `question_type`, `verification_status`, and user progress lookup columns, plus PostgreSQL `GIN` indexes on `JSONB` columns and Full-Text Search (`tsvector`) indexes supporting `GET /api/search?q=present+simple`.
4. **Audit Timestamps & Soft Deletion**: Every table includes `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` and `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` (maintained by an automated PostgreSQL trigger), with `deleted_at TIMESTAMPTZ` soft deletion on core content and user tables.
5. **Lossless Source Traceability**: Every migrated record stores `source_file`, `start_line`, `end_line`, and `raw_markdown` / `original_answer_text` alongside structured relational fields, ensuring zero silent data loss and full auditability against `Ngữ pháp tiếng anh - Mai Lan Hương -Hà Thanh Uyên (Bản word full).md`.
6. **Strategic Use of `JSONB`**: Core educational entities (lessons, rules, examples, exercises, questions, options, answers) live in normalized relational tables. `JSONB` is reserved strictly for genuinely flexible payloads: `lesson_sections.structured_blocks`, `questions.metadata`, `question_answers.alternative_answers`, and `user_question_attempts.submitted_payload`.

## 2. Logical Domain Breakdown (5 Core Domains, 21 Tables)

### Domain A: Book Management (Source Traceability Layer)
Preserves the exact physical structure of the original textbook independently of how topics are categorized in the learning UI:
- **`books`**: Stores book-level metadata (`title`, `authors`, `edition_note`, `source_file`, `total_lines`, `checksum`).
- **`book_chapters`**: Stores the 12 major chapters of the book (`chapter_number`, `code`, `title_en`, `title_vi`, `original_heading`, `start_line`, `end_line`, `checksum`).
- **`book_sections`**: Stores the 53 structural subdivisions within chapters (`section_number` e.g. `1.1`, `code`, `title_en`, `title_vi`, `section_type`, `start_line`, `end_line`).

### Domain B: Grammar Knowledge (Pedagogical & Curriculum Layer)
Models hierarchical grammar topics and rich, reusable lesson content without forcing book chapters into artificial flat buckets:
- **`grammar_categories`**: Top-level pedagogical domains (e.g., *Verbs & Tenses*, *Clauses & Phrases*, *Determiners & Quantifiers*, *Parts of Speech*, *Word Study, Formation & Idioms*, *Sentence Structure, Voice & Style*, *Comprehensive Practice*).
- **`grammar_topics`**: Self-referencing hierarchical topic tree (`parent_topic_id REFERENCES grammar_topics(id)`), supporting arbitrary depth (`Grammar -> Verbs & Tenses -> Tenses -> Present Simple`) while optionally linking to `book_chapters`.
- **`lessons`**: Individual learning units (`53` lessons) belonging to a `grammar_topic`, `book_chapter`, and `book_section`.
- **`lesson_sections`**: Granular sections within a lesson (`491` sections, typed via `LessonSectionType`: `OVERVIEW`, `FORMULA_AND_FORM`, `USAGE`, `GRAMMAR_FORM`, `SIGNAL_WORDS`, `NOTE`, `CLASSIFICATION`, `FUNCTION`, `THEORY`). Stores both `raw_markdown` and `structured_blocks` (`JSONB`).
- **`grammar_rules`**: Searchable, addressable grammar rules and syntactic formulas (`982` rules, typed via `GrammarRuleType`: `FORMULA`, `USAGE_RULE`, `CONSTRAINT_NOTE`, `THEORY_SUMMARY`). Can be referenced directly by `answer_explanations` and AI tutoring features.
- **`examples`**: Reusable bilingual example sentences (`1,026` examples) linked to `lessons`, `lesson_sections`, and `grammar_rules`, storing `sentence_en`, `sentence_vi`, and `negative_example_note` (e.g. `[NOT ...~~am-being~~]`).
- **`lesson_tables`**: Stores extracted Markdown tables (`7` theory tables) with structured `rows_json` (`JSONB`) and `raw_markdown` so tables are never lost or mangled.

### Domain C: Exercise Management (Multi-Format Assessment Layer)
Designed around all **12 question types** rather than multiple-choice only:
- **`exercise_groups`**: Represents each `# EXERCISES` or `# PRACTICE TEST` collection block (`31` groups), preserving both exercise line ranges and answer key line ranges (`answer_start_line`, `answer_end_line`).
- **`exercises`**: Individual numbered/Roman-numeral exercises (`134` exercises) within an exercise group, storing `roman_numeral`, `original_label` (preserving source typos like `III` for `II`), `instruction_en`, `instruction_vi`, `exercise_type` (`QuestionType` enum), and anomaly flags.
- **`questions`**: Individual questions (`2,939` questions) supporting single-blank, multi-blank (`blank_count`), passage-based cloze (`metadata.is_passage`), sentence transformation (`starter_prompt`), word formation (`root_word`), and embedded base64 fraction images (`metadata.contains_base64_image`).
- **`question_options`**: Option choices (`327` records) for `MULTIPLE_CHOICE` and `TRUE_FALSE` questions, including `blank_index` (so a question with multiple parenthetical choice groups `(opt1/opt2) ... (opt3/opt4)` links each option to its specific blank!).

### Domain D: Answer Management (Verification & Audit Layer)
Enforces strict separation between verified textbook answers, alternative acceptable answers, and items requiring human review:
- **`question_answers`**: Stores the canonical answer (`correct_answer`), verbatim textbook string (`original_answer_text`), `alternative_answers` (`JSONB` array of valid variants), `blank_index` (supporting multi-blank questions), `is_verified` (`BOOLEAN`), `verification_status` (`VERIFIED`, `NEEDS_REVIEW`, `UNVERIFIED`), `review_note`, and `source_line`.
- **`answer_explanations`**: Stores English and Vietnamese explanations (`explanation_vi`, `explanation_en`), optional `grammar_rule_id` foreign key linking the answer to the exact grammar rule it tests, and `source_type` (`BOOK_ANSWER_KEY`, `EDITORIAL_MANUAL`, `AI_GENERATED`).

### Domain E: Future Learning & Spaced Repetition Layer
Supports user progress tracking, quiz submissions, bookmarks, and SM-2/FSRS spaced repetition without schema redesign:
- **`users`**: Platform learners and administrators (compatible with Supabase Auth `auth.users` UUIDs).
- **`user_lesson_progress`**: Tracks per-user lesson completion status (`NOT_STARTED`, `IN_PROGRESS`, `COMPLETED`), time spent, and mastery score.
- **`user_exercise_results`**: Tracks quiz/exercise session submissions (`POST /api/exercises/:id/submit`), score percentage, and completion timestamps.
- **`user_question_attempts`**: Granular log of individual question answers (`POST /api/questions/:id/answer`), storing `submitted_answer`, `is_correct`, `matched_answer_id`, and `time_taken_ms`.
- **`user_bookmarks`**: Polymorphic or multi-FK bookmark table allowing users to bookmark `lessons`, `grammar_rules`, or `questions` with personal notes.
- **`review_schedule`**: Spaced repetition schedule (`easiness_factor`, `interval_days`, `repetitions`, `next_review_at`, `last_reviewed_at`) for adaptive review of lessons, rules, and questions.

## 3. Web API Compatibility & Query Mapping (STEP 7)

| Endpoint | HTTP | Primary Tables & Joins | Indexing & Performance Strategy |
| :--- | :---: | :--- | :--- |
| `GET /api/chapters` | `GET` | `book_chapters` + `LEFT JOIN book_sections` + `COUNT(lessons)` | Ordered by `chapter_number ASC`; indexed on `(book_id, chapter_number)` |
| `GET /api/grammar/categories` | `GET` | `grammar_categories` + `grammar_topics (hierarchy_level = 1)` | Ordered by `display_order ASC` |
| `GET /api/grammar/topics` | `GET` | `grammar_topics` recursive CTE or 2-level self-join (`parent_topic_id`) | Indexed on `category_id`, `parent_topic_id`, `display_order` |
| `GET /api/lessons/:id` | `GET` | `lessons` + `lesson_sections` + `grammar_rules` + `examples` + `lesson_tables` | Single query with Prisma `include` ordered by `display_order` |
| `GET /api/lessons/:id/exercises` | `GET` | `exercise_groups` + `exercises` filtered by `lesson_id` or `topic_id` | Indexed on `exercises(lesson_id, display_order)` |
| `GET /api/exercises/:id/questions` | `GET` | `exercises` + `questions` + `question_options` (omitting `question_answers` in quiz mode, or including in review mode) | Indexed on `questions(exercise_id, question_number)` and `question_options(question_id, blank_index)` |
| `GET /api/search?q=present+simple` | `GET` | `grammar_topics`, `lessons`, `grammar_rules`, `examples`, `questions` | Uses PostgreSQL `GIN` Full-Text Search index (`search_vector`) + `pg_trgm` trigram index for bilingual EN/VI matching |
| `GET /api/user/progress` | `GET` | `user_lesson_progress`, `user_exercise_results`, `review_schedule` | Indexed on `(user_id, status)` and `(user_id, next_review_at)` |
| `POST /api/exercises/:id/submit` | `POST` | Evaluates answers against `question_answers` (`correct_answer` + `alternative_answers`), writes `user_exercise_results` + `user_question_attempts` in a transaction | Sub-10ms evaluation via indexed `question_answers(question_id, blank_index)` |
| `POST /api/questions/:id/answer` | `POST` | Checks single question against `question_answers` + returns `answer_explanations` & linked `grammar_rules`; updates `review_schedule` | Transactionally logs `user_question_attempts` and updates spaced-repetition interval |
